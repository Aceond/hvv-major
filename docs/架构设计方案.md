# HVV Major · CS2 电竞赛事管理系统 — 架构设计方案

> 版本：v0.3（框架阶段 · CS2 领域版 · 数据手动录入）
> 目标：面向 CS2 赛事的一站式平台，覆盖**战队报名**、**赛程赛制**、**积分排名**，管理后台负责审核与运维。

---

## 1. 项目概述

| 模块 | 说明 |
|---|---|
| 报名模块 | 选手在线组建战队、填写名册（灵活人数 ≥5），管理员审核 |
| 数据模块 | 战队/名册数据、比赛结果、手动录入的比赛与个人统计 |
| 比赛模块 | 多阶段混合赛制（海选循环赛 → 淘汰赛）、对阵管理、比分录入、积分榜 |

用户角色：
- **选手/游客**（公开端）：浏览公告、报名组队、查看赛程与积分榜
- **管理员**（管理端）：审核战队、配置阶段与对阵、录入比分与统计数据

---

## 2. 技术选型与部署架构

| 层 | 技术 | 说明 |
|---|---|---|
| 前端框架 | Vue 3 + TypeScript | 组合式 API |
| 构建工具 | Vite | 产物为纯静态文件，可直接部署 GitHub Pages |
| UI 组件库 | Element Plus | 表格/表单/后台管理场景友好 |
| 路由/状态 | Vue Router 4 + Pinia | 公开端 + 管理端分区 |
| **后端** | **Supabase** | PostgreSQL + Auth + 行级安全(RLS) + 实时订阅 |
| 部署 | GitHub Actions → GitHub Pages | push 自动构建发布 |

> GitHub Pages 只能托管静态文件，后端采用 BaaS（Supabase）无需自建服务器。
> 若目标用户全部在国内且对稳定性要求高，可迁移到「Cloudflare Pages + 腾讯云开发」，前端仅需替换 API 层。

### 数据录入方案

比赛结果与统计数据由**管理员在后台手动录入**，不依赖第三方平台接口：

- **赛程管理**（[admin/Matches.vue](src/views/admin/Matches.vue)）：新建阶段/对阵、录入比分（胜者由系统按比分判定）
- **数据录入**（[admin/Stats.vue](src/views/admin/Stats.vue)）：
  - 队伍数据：按组别+阶段录入 场次/胜/负/积分/**WE%/ADR/KD/Rating**
  - 个人数据：按战队筛选名册，录入 场次/击杀/死亡/助攻/爆头率/**Rating**，按完美用户名记录
  - 支持"总阶段"汇总视图，与单个阶段数据并列展示
- 录入数据按 `(team_id, stage_id)` / `(player_id, stage_id)` 幂等 upsert，重复保存不产生脏数据
- 后续如需对接对战平台（完美/5E/FACEIT），可保留 `src/api/sync.ts` 作为扩展点，不影响现有录入链路

## 4. 数据库设计

### 4.1 表结构

```
auth.users        -- Supabase 内置账号
  └─ profiles     -- 用户资料（角色 admin/player，含昵称与完美用户名）
teams             -- 战队（队长 + 审核状态 + 所属组别）
team_members      -- 战队名册（灵活人数，≥5 参赛）
groups            -- 组别（传奇组 / 大师组 / 挑战组，相互独立）
stages            -- 阶段（海选/预选/正赛，格式可不同）
matches           -- 对阵（BO1/BO3，比分、胜者、状态）
team_stats        -- 队伍统计数据（WE/ADR/KD，手动录入）
player_stats      -- 个人统计数据（击杀/死亡/助攻等，手动录入）
standings         -- 积分榜视图（胜=3分，自动计算）
```

| 表 | 关键字段 | 说明 |
|---|---|---|
| profiles | `role` ('admin'/'player'), `nickname`, `pw_username` | 注册触发器自动创建 |
| teams | `name`, `tag`, `captain_id`, `group_id`, `status`(pending/approved/rejected) | 报名后待审核 |
| team_members | `profile_id`, `is_captain` | 名册，同队去重 |
| groups | `name`, `sort_order` | 三组独立赛区 |
| stages | `name`, `format`(round_robin/single_elim/double_elim/swiss), `status` | 多阶段混合赛制 |
| matches | `stage_id`, `group_id`, `round_number`, `team_a_id/b_id`, `best_of`, `map`, `team_a_score/b_score`, `winner_id`, `status` | team_b 为 NULL 表示轮空 |
| team_stats | `team_id`, `stage_id`, `we`, `adr`, `kd`, `rating` | 按 (team_id, stage_id) 去重，手动录入 |
| player_stats | `profile_id`, `stage_id`, `kills`, `deaths`, `assists`, `hs_rate`, `rating` | 按 (profile_id, stage_id) 去重，手动录入 |

### 4.2 权限模型（RLS）

| 表 | 游客 | 登录选手 | 管理员 |
|---|---|---|---|
| teams | 只读 | 建队/管理自己的队伍 | 全量（审核） |
| team_members | 只读 | 加入/维护自己队伍名册 | 全量 |
| groups / stages / matches | 只读 | 只读 | 全量 |
| team_stats / player_stats | 只读 | 只读 | 全量（录入） |
| standings | 只读 | 只读 | 只读 |

比分与统计数据写入由管理员账号（RLS）直接 upsert，前端仅管理员界面可发起录入。

## 5. 前端架构

### 5.1 路由规划

```
/                首页（公告/入口）
/player-register 个人选手注册（完美用户名）
/register        战队报名（建队 + 从选手池选人，名册 ≥5 人）
/matches         赛程（按阶段/组别筛选展示对阵与比分）
/standings       积分榜（按阶段/组别，Realtime 实时刷新）
/rankings        数据排行（队伍/个人，按组别与阶段筛选）
/login           登录 / 注册（演示模式可直接以角色进入）
/admin           管理端（角色守卫）
├─ /admin         仪表盘（战队/场次/阶段统计）
├─ /admin/teams   战队审核（名册展开查看 + 通过/拒绝 + 调整组别）
├─ /admin/matches 赛程管理（阶段/对阵/比分录入）
└─ /admin/stats   数据录入（队伍 WE/ADR/KD + 个人击杀/死亡等）
```

### 5.2 目录结构

```
hvv-major/
├─ docs/                      # 本设计文档
├─ supabase/schema.sql        # 数据库初始化脚本
├─ .github/workflows/deploy.yml
└─ src/
   ├─ api/                    # registration(报名) / match(赛程积分) / admin / stats(数据录入) / sync(扩展占位) / types
   ├─ mock/data.ts            # 本地演示数据
   ├─ stores/auth.ts          # 登录态（含演示登录）
   ├─ layouts/                # 公开端 / 管理端布局
   └─ views/                  # Home / PlayerRegister / Register / Matches / Standings / Rankings / Login + admin/*
```

### 5.3 关键点

- 路由守卫：`/admin/**` 校验 `role === 'admin'`
- 积分榜实时刷新：订阅 `matches` 表变更
- 数据录入：`src/api/stats.ts` 按 (team_id, stage_id) / (profile_id, stage_id) 幂等 upsert，管理端 [admin/Stats.vue](src/views/admin/Stats.vue) 提供行内编辑
- 演示模式：未配置 Supabase 密钥时，API 层返回 mock 数据；登录页提供"以管理员/选手身份进入"

## 6. 部署方案

1. GitHub Actions：push `main` → `npm ci && npm run build` → 部署 `gh-pages` 分支
2. Supabase：创建项目 → SQL Editor 执行 `supabase/schema.sql` → 设置管理员
3. Secrets：`VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`
4. 本地开发：复制 `.env.example` 为 `.env.local` 填入密钥
