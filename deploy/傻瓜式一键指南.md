# HVV Major 迁移 · 傻瓜式一键指南

> 不用懂原理，跟着做。每步都是"复制 → 粘贴 → 回车"。
> 全程在**你的 140 服务器**上操作。

---

## 第 0 步：把文件传上去

用你的 SFTP 工具（端口 2022），把 `hvv-backend-deploy.tar.gz` 传到服务器的 `/opt` 目录下。

传完后，登录服务器（SSH），一条条执行下面命令。

---

## 第 1 步：解压

```bash
mkdir -p /opt/hvv-backend && cd /opt/hvv-backend && tar -xzf /opt/hvv-backend-deploy.tar.gz
```

---

## 第 2 步：一键生成配置（复制整段粘贴回车）

把下面**整段**复制粘贴进终端，回车。它会自动生成所有随机密码，你什么都不用改：

```bash
cd /opt/hvv-backend
# 生成随机密钥
JWT=$(openssl rand -hex 64)
PG=$(openssl rand -hex 32)
AUTHEN=$(openssl rand -hex 32)
AUTHD=$(openssl rand -hex 32)
RT=$(openssl rand -hex 32)
# 服务器 IP（下面这行改成你的真实公网 IP，别的不用动）
IP=140.143.184.247

cat > .env <<EOF
SITE_URL=http://${IP}:8000
URI_ALLOW_LIST=http://${IP}:8000,http://localhost:5173,https://major.hwmajor.club
JWT_SECRET=${JWT}
POSTGRES_PASSWORD=${PG}
AUTHENTICATOR_PASSWORD=${AUTHEN}
AUTH_DB_PASSWORD=${AUTHD}
REALTIME_DB_PASSWORD=${RT}
MAILER_AUTOCONFIRM=true
EOF

# 把 init.sql 里的密码占位符换成刚生成的真实值
sed -i "s/__AUTHENTICATOR_PASSWORD__/${AUTHEN}/g; s/__AUTH_DB_PASSWORD__/${AUTHD}/g; s/__REALTIME_DB_PASSWORD__/${RT}/g" init.sql

# 打印出来让你看一眼（记下 JWT_SECRET，前端要用）
cat .env
echo "---- 记下上面那行 JWT_SECRET= 的值，第 6 步要用 ----"
```

> 注意：上面 `IP=140.143.184.247` 这行，确认是你的公网 IP。如果不是，改掉它再粘贴。

---

## 第 3 步：起数据库 + 建角色

```bash
cd /opt/hvv-backend
docker compose up -d postgres
sleep 10
docker exec -i hvv-postgres psql -U postgres -d postgres < init.sql
```

看到最后输出 `角色与 auth.users 表已就绪。` 就说明成功了。

---

## 第 4 步：导出 Supabase 云数据（密码已填好，直接跑）

```bash
cd /opt/hvv-backend
bash dump-from-supabase.sh
```

等它跑完（几十秒到几分钟），出现 `导出完成` 就成功，目录下会多一个 `dump.sql`。

---

## 第 5 步：恢复到自建库

```bash
cd /opt/hvv-backend
# 从 .env 里读 postgres 密码，自动填进恢复脚本
PGPW=$(grep '^POSTGRES_PASSWORD=' .env | cut -d= -f2)
sed -i "s/REPLACE_ME/${PGPW}/" restore-to-self.sh
bash restore-to-self.sh
```

最后会打印四行数字（users / teams / matches / applications），有数字说明数据进来了。

---

## 第 6 步：启动全部服务

```bash
cd /opt/hvv-backend
docker compose up -d
sleep 15
docker ps | grep hvv
```

看到 5 个 `hvv-` 开头的容器都是 `Up` 状态，就成功了。

---

## 第 7 步：验证

```bash
curl http://140.143.184.247:8000/rest/v1/
```

返回一堆 JSON（`swagger` / `definitions` 之类的）就说明 API 通了。

## 最后：改前端两个变量

打开项目前端的 `.env.local`（或 GitHub 仓库的 Secrets），把两个值改成：

```
VITE_SUPABASE_URL=http://140.143.184.247:8000
VITE_SUPABASE_ANON_KEY=<anon JWT>
```

### 自己生成 anon key（不用发密钥给任何人）

在服务器上，**整段复制粘贴**下面这段，它会用你第 2 步的 `JWT_SECRET` 自动算出 anon key 并打印出来：

```bash
cd /opt/hvv-backend
# 读取第 2 步生成的 JWT_SECRET
JWT=$(grep '^JWT_SECRET=' .env | cut -d= -f2)

# 用 node 签一个 {"role":"anon"} 的 JWT（HS256，无过期时间，与 Supabase anon key 同款）
node -e "
const c=require('crypto');
const s='$JWT';
const b64u=(o)=>Buffer.from(JSON.stringify(o)).toString('base64url');
const h=b64u({alg:'HS256',typ:'JWT'});
const p=b64u({role:'anon',iss:'supabase'});
const sig=c.createHmac('sha256',s).update(h+'.'+p).digest('base64url');
console.log('ANON KEY =', h+'.'+p+'.'+sig);
"
```

打印出来的 `ANON KEY =` 后面那一长串，就是 `VITE_SUPABASE_ANON_KEY` 的值，直接填进前端。

> 注意：服务器上要有 `node`。如果没有，用 `docker run --rm node:22-alpine node -e "..."` 代替也行（把上面 `node -e` 换成 `docker run --rm -e S="$JWT" node:22-alpine node -e "..."`，脚本里用 `process.env.S` 代替 `'$JWT'`）。

## 出问题怎么办

| 症状 | 排查 |
|---|---|
| 第 3 步没看到"已就绪" | `docker logs hvv-postgres` 看报错 |
| 第 4 步连不上云 | 服务器能否 `ping db.spljjoalknnblltesuux.supabase.co`；若被墙需服务器挂代理 |
| 第 6 步有容器退出 | `docker logs hvv-gotrue` / `docker logs hvv-realtime` 看报错 |
| 登录成功但查不到数据 | 99% 是 JWT_SECRET 三处没对齐，回第 2 步重来 |
